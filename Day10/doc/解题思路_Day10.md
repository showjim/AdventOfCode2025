# Day 10: Factory — 解题思路

> 答案：Part 1 = **484**，Part 2 = **19210**（示例 test_input.txt 分别为 **7** 和 **33**）

---

## Part 1 —— 指示灯（位掩码 + BFS）

### 问题模型
- 一盏灯只有 **开/关** 两种状态。把「灯亮」记成 1、「灯灭」记成 0。
- 每个按钮会 **翻转(toggle)** 一组灯（0→1、1→0）。
- 一台机器目标图 `[.##.]` = 希望灯 1、灯 2 亮，灯 0、灯 3 灭。
- 问：最少按几次按钮，能让灯正好变成目标状态？

### 关键洞察
1. **按同一个按钮两次 = 没按**（翻转两次回到原状）。所以每个按钮只有两种选择：按 1 次 / 不按。问题变成「选一组按钮，让它们的翻转效果恰好等于目标」。
2. 灯的亮灭组合用**位掩码(bitmask)** 表示：一个 `int` 的每一位代表一盏灯。`.##.` = 二进制 `0110` = 整数 `6`。
3. 一次「按按钮」= 用 XOR 翻转：`newState = state ^ buttonMask`。因为 `a ^ a = 0`，XOR 正好就是"翻转"。
4. 状态空间只有 **2^(灯数)** 个（4 盏灯 → 16 个状态），很小。

### 算法：BFS（广度优先）
把所有可能的灯状态当作「点」，按一次按钮就是从当前点走到另一个点。要求「最少的按键次数」，就是 BFS：先看按 1 次能到哪些状态，再看 2 次……**第一次遇到目标状态时，那个深度就是最少次数**。

用 `dist[state]` 记录到达每个状态的最少按键数，队列保证按距离从小到大访问；每个状态只访问一次。

## Part 2 —— 电压计数器（整数线性规划 ILP）

### 问题模型
计数器从 0 开始，每按一次按钮 j，就会给 `B_j`（它列出的那些计数器）**各 +1**。
设 `x_j` = 按按钮 j 的次数，那么对每个计数器 c 都要满足：

```
Σ (对含有 c 的按钮 j)  x_j  =  t_c        (t_c 是 c 的目标值)
```

目标：**最小化 Σ x_j**。

也就是说：每个计数器只能靠「加」到恰好目标值，不能减少；按钮可以按任意多次。这不是 Part 1 那种 0/1 选择了 —— **一个按钮按 2 次和按 0 次完全不同**。

### 为什么不能再用 BFS 搜状态
Part 1 的状态是 2^n 个。Part 2 的"状态"是每个计数器的数值，范围从 0 到目标值（真实输入里目标值可到 **~300**）。10 个计数器就是 ~300^10 个状态 —— 天文数字，BFS 直接爆掉。

> 实测：单是 34 号机器，用状态 BFS 在深度 12 时搜索前沿就已经有 1000 万个状态，而最优解要按 313 次。任何"枚举状态"的做法都不可行。

### 数学抽象：这是一个整数线性规划
上面那个问题就是经典的 **ILP**：
- 变量 `x_j`：≤ 13 个，要求是**非负整数**；
- 约束：≤ 10 条等式；
- 目标：最小化 `Σ x_j`。

n 个变量、m 条等式的 ILP 通常用**分支定界(branch & bound)** 求解：

#### 1) 线性松弛(LP relaxation)给出下界
暂时允许 `x_j` 取**实数**，解出来的最小值记作 `V`。任何整数解都不可能小于 V，所以 V 是一个**下界**。
- 如果 LP 的解正好全是整数 → 它就是最优解，直接得到答案。（真实输入里 186 台中 166 台都是这种情况！）
- 如果 LP 解里有分数（比如某按钮按了 7.3 次）→ 需要继续分支。

#### 2) 分支(branch)：对分数变量一分为二
假设 LP 说 `x_5 = 7.3`。整数解里 `x_5` 只可能是 `≤ 7` 或 `≥ 8`，于是把问题拆成两个子问题：
- 子问题 A：限制 `x_5 ≤ 7`；
- 子问题 B：限制 `x_5 ≥ 8`。

整数最优解一定落在其中一个子问题里 —— **没有丢失任何可能性**。

#### 3) 定界 & 剪枝(prune)
递归求解子问题。一旦某个子问题的（下界 + 已经确定的按键数）≥ 已经找到的最好整数解，就**整棵剪掉**——因为里面不可能有更好的答案。

### 代码里几个有意思的实现细节
- **LP 松弛怎么解？** 用「枚举基解」：一个只有 m≤10 条等式的最优解，一定出现在某个「选 m 个按钮解 m 元方程组」的基解里，组合数最多 C(13,10)≈286 个，穷举即可，又快又精确。
- **高斯消元去重/查矛盾**：有些计数器的约束是重复的（某些灯/计数器的按钮组合完全相同），先做行化简，若有矛盾行则无解。
- **强制传播(propagation)**：如果某个计数器只被**唯一一个**剩余按钮触碰，那这个按钮的按键次数就被**锁死**了，可以立刻确定、缩小搜索。
  - 注意这里有个经典的坑：减法循环里如果写成 `r[cc] -= r[c]`，当遍历到 `cc==c` 时 `r[c]` 已经被改成 0，后面所有计数器都减了个 0 —— 必须先 `int amt = r[c]` 存下来再减。这也是真实调试中抓到的 bug。
- **分支策略**：选 LP 解里**小数部分最接近 0.5** 的变量来分支（标准 MILP 做法），搜索树会小很多。

### 为什么这么慢的问题也能瞬间跑完
真实的难点全部被「好的下界 + 强制传播 + 好的分支」化解了：
- 多数机器 LP 松弛本身就是整数解 → 不用搜；
- 少数需要搜索的机器，LP 下界离最优解只差不到 7（实测），剪枝非常狠 → 186 台机器总耗时 < 0.2 秒。

## 小结：两道题的思维对照

| | Part 1 灯 | Part 2 计数器 |
|---|---|---|
| 状态 | 2^n 个（位掩码） | 数值巨大，无法枚举 |
| 按钮效果 | 翻转（XOR，按 2 次=没按） | 加 1（按 k 次=k 次，次数很重要） |
| 数学本质 | 集合覆盖 / BFS 最短路径 | 整数线性规划（ILP） |
| 算法 | BFS + 位掩码 | 分支定界 + LP 松弛下界 |

**核心收获**：同样的问题，一旦规则从"翻转"变成"累加"，就从"有限状态图的最短路"变成了"整数线性规划"——识别问题的数学本质，比急着写代码更重要。
